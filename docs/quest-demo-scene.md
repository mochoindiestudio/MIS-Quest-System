# Quest Demo Scene — "Water from the Well"

A small 2D mini-game in `Assets/QuestSystemDemo/` that drives the MIS Quest System end to end, so
its behaviour can be eyeballed in Play mode. It is **not** part of the shipped package (a trimmed
`Samples~` version is Phase 4 on `ROADMAP.md`).

## The quest

`WellQuest` (asset: `Assets/QuestSystemDemo/Data/WellQuest.asset`) — 5 linear objectives, auto-started
by its list `WaterFromTheWell` (`autoAdvance = true`):

| # | Objective | Completes on |
|---|---|---|
| 0 | Find a wooden bucket | `MisSignals.Report("item_collected", "bucket")` |
| 1 | Find a length of rope | `... ("item_collected", "rope")` |
| 2 | Craft a bucket on a rope | `... ("item_crafted", "bucket_on_rope")` |
| 3 | Find the old well | `... ("reached", "well")` |
| 4 | Lower the bucket into the well | `... ("used", "well")` |

On completion `DemoGame.HandleQuestCompleted` adds **Bucket of Water** to the inventory — the reward
is game-side, exactly as the package intends.

## Controls

| Key | Action |
|---|---|
| WASD / arrows | move |
| **E** | interact with the nearest highlighted object |
| **TAB** | quest log (scrolls when objectives overflow) |
| **I** | inventory (+ the Craft button) |
| **F1** | controls panel (top-right, shown by default) |
| **ESC** | pause menu (Restart / Quit) |

The **Help panel** (top-right, visible on start, F1 to toggle) lists these keys. The **Quest log**
sits just below it and its objective list scrolls; completed objectives show a green check-mark icon
(Unity's `UI/Skin/Checkmark`).

## How the scene is built

The scene is generated by a re-runnable editor script, **not** hand-edited:

> **`Tools ▸ Quest Demo ▸ Build Scene`** — rebuilds `Assets/QuestSystemDemo/Scenes/QuestDemo.unity`
> from `DemoSpriteMap.asset` and the data assets.

Because the scene is regenerated, **do not tweak it directly** — change `DemoSpriteMap` or the layout
constants at the top of `Assets/QuestSystemDemo/Editor/DemoSceneBuilder.cs` and rebuild.

### Art mapping

`ClassicRPG_Sheet.png` is 16 px sprites, pre-sliced as `ClassicRPG_Sheet_0 … _127`.
`DemoSpriteMap.asset` is filled from the real mapping:

| Field | Sheet indices |
|---|---|
| `player` down / left / right / up | 0–3 / 20–23 / 39–42 / 58–61 |
| `grass` (3×3) | 24,25,26 / 43,44,45 / 62,63,64 |
| `dirt` (3×3) | 77,78,79 / 93,94,95 / 108,109,110 |
| `dirtPath` (straights / corners, hand-placed) | 80–84 |
| `bigTree` (2×2) | 99,100 / 114,115 |
| `smallTree` (1×2) | 101 / 116 |
| `rock1` / `rock2` | 102 / — (203 is out of range on this 128-sprite sheet) |
| `decor` (hand-placed) | 7, 8, 27, 28, 117, 118, 120 |
| `well` (1×2) | 88 / 105 |
| `bucket` / `rope` | 104 / 122 |

Change any field in the Inspector and run **Build Scene** again — the builder only reads it.

### Tilemaps, palette & sorting

The map is 34×24 cells, camera size 8. Four tilemaps under `Grid`:

| Tilemap | Order | Notes |
|---|---|---|
| `Ground` | −20 | grass fill; **`Chunk`** renderer; `TilemapCollider2D` + static `Rigidbody2D` |
| `Paths` | −10 | empty — paint the dirt path here |
| `Decor` | 0 | trees / rocks / props / well; **`Individual`** renderer (Y-sorts vs player); `TilemapCollider2D` + static `Rigidbody2D` |

The builder creates a real **Tile Palette** at `Assets/QuestSystemDemo/Art/Palettes/QuestDemo.prefab`
(all `QD_*` tiles laid out) and one clean tile asset per role in `Art/Tiles/` (no duplicates).
`Window ▸ 2D ▸ Tile Palette` → pick **QuestDemo** → pick the `Paths` (or `Decor`) tilemap → paint.

**Colliders.** A tile is solid **only where the sprite has a Custom Physics Shape**. The builder
asks for `ColliderType.Sprite` on every grass / tree / rock / decor / well tile, then
`SharedTile` **downgrades it to `None` when `sprite.GetPhysicsShapeCount() == 0`** — because this
sheet imports as `FullRect`, so `ColliderType.Sprite` on a shapeless sprite would otherwise fall back
to a full-tile block. Dirt and path tiles are always `None`.

So: draw a Custom Physics Shape (Sprite Editor ▸ *Custom Physics Shape*) on the grass **edge** sprites
for the map limit, on the tree **trunk** tiles, on the rock, on the well base — and **rebuild**.
Anything you don't shape stays walkable. The `Well` GameObject has **no collider of its own**; its
solidity is entirely the base tile's shape.

**Y-sorting.** `GraphicsSettings` transparency sort is set to Custom Axis `(0,1,0)` and the camera
matches, so the player draws behind a tree whose base is above them and in front of one below. The
`Decor` tilemap renderer is `Individual` so each tree tile sorts by its own cell. (Set the tree
sprites' pivots to *Bottom* for the cleanest result.)

## Playtest checklist

1. Enter Play mode. The **Help panel** shows top-right; **F1** hides/shows it. The quest log (TAB)
   shows all 5 objectives — #0 highlighted with "▸", the rest dimmed. A toast reads
   **"New objective available! Check your Quest Book."**
2. Walk onto the **bucket** → prompt "[E] Pick up Wooden Bucket" → press E. Objective 0 gets a green
   check-mark icon; objective 1 lights up; toast fires again.
3. Same for the **rope**.
4. Press **I** → the **Craft bucket on a rope** button is now enabled → click it. Bucket + rope
   leave the bag, "Bucket on a Rope" appears; objective 2 completes, objective 3 lights up.
5. Walk to the **well**. On entering its ring, objective 3 completes and objective 4 lights up. The
   prompt reads "Lower the bucket into the well".
6. Press **E** at the well → the **Bucket on a Rope** is consumed → objective 4 completes → quest
   completes → a **"Bucket of Water"** appears in the inventory and a completion toast shows.
7. **TAB** / **I** toggle their panels. **ESC** opens the pause menu and freezes the game; **Restart**
   reloads the scene; **Quit** exits Play mode (or the player build).

## Known rough edges

- **TAB** is also uGUI's focus-navigation key; harmless here (the HUD is mouse-driven) but rebind
  `questLog` in `DemoInput` if it ever misbehaves.
- `rock2` is unset (`ClassicRPG_Sheet_203` is past the 128-sprite sheet).
- Tile collider types are baked at **build time** from the current physics shapes — edit a shape,
  then re-run *Build Scene* for it to take effect.
